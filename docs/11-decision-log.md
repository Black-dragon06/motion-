# 11 · Decision log

Every significant decision, the alternatives considered, and why. Format:
**Decision — alternatives — reasons — consequences.**

---

### D1 · Stack: HTML/CSS/SVG + JS timeline, rendered by Playwright, encoded by ffmpeg
*Alternatives:* Remotion (React video), canvas 2D drawing, Python (Pillow/moviepy/Cairo), After Effects scripting, Lottie.
*Reasons:* Chromium already installed with Playwright; best-in-class text rendering, gradients, SVG paths,
blur filters, clip-paths with zero dependencies; no build step (plain ES modules); inspectable DOM
(you can ask an element where it is); pixel-deterministic screenshots. Remotion would add React + a bundler
for the same rendering engine. Canvas/Pillow would mean re-implementing text layout and filters.
*Consequence:* the "engine" is ~300 lines (`composition/lib/core.js`) + an 80-line renderer.

### D2 · Every frame is a pure function `update(f)`
*Alternatives:* CSS animations/transitions, GSAP timelines played in real time and captured.
*Reasons:* real-time capture drops frames and depends on machine speed; CSS animations can't be seeked
exactly; a pure function renders any frame in any order (needed for `--list` QA renders).
*Consequence:* strict rules (no timers, no random, reset everything each frame — `docs/05-engine-api.md`).

### D3 · Reuse the reference soundtrack
*Alternatives:* none sensible — the voice-over and SFX are content, not motion.
*Consequence:* the motion must be frame-exact or it visibly drifts from the voice.

### D4 · LIFT footage from the reference, DRAW everything designed
*Alternatives:* approximate backgrounds with gradients/blurred stock; generative imagery.
*Reasons:* footage (hills, paintings, characters) can't be generated by code; approximations were tried
for the close-up background (scaled intro plate + haze gradient) and scored 17.4 vs 9.6 with lifted
plates. Lifting keeps the photographic layers exact and puts all effort into the graphics.
*Consequence:* `scripts/extract_plates.py` + push-pull inpainting; plates replaceable by originals.

### D5 · Inter / Inter Display as the SF Pro substitute, fonts bundled
*Alternatives:* system fonts, Helvetica/Arial, licensing SF Pro.
*Reasons:* SF Pro is not redistributable; Inter is OFL, has a Display optical size, near-identical
proportions. Bundling avoids machine-dependent rendering.
*Consequence:* ~5–8% width difference compensated per element (`placeText`, glyph remap).

### D6 · Per-frame measured keyframes with linear interpolation, fitted laws only when they fit
*Alternatives:* designing easing curves by eye; fitting everything to bezier curves.
*Reasons:* linear interpolation between per-frame measurements reproduces the reference exactly,
including irregularities. A fitted law is used only when it fits within ~1 px and makes code clearer
(intro words: exp settle r = 0.9, RMSE 0.87 px).
*Consequence:* long keyframe arrays — kept readable with one key per frame and comments, or moved to
`composition/data/`.

### D7 · Camera = group transform around the measured fixed point
*Alternatives:* moving each element separately.
*Reasons:* the reference moves everything together during pushes/whips; one transform keeps the
relative layout exact; the fixed point is measurable.

### D8 · Letterbox as a global layer in `main.js`
*Reasons:* it animates across scene boundaries (e.g. 238–312 spans "But…", typing, Life saver).

### D9 · Scene files per block; "But…" and typing share one file
*Reasons:* one file per block keeps context small. "But…" and typing are joined because the card
of one becomes the caret of the other — continuity across the boundary is easier in one module.

### D10 · Montage as a shot registry with shared helpers
*Reasons:* 19 shots with the same hero button geometry, caption and label rules; helpers make
each shot 5–30 lines and guarantee consistency.

### D11 · Cursor traced from the reference, sized per scene
*Alternatives:* OS cursor image, emoji, a generic SVG hand.
*Reasons:* the generic hand was the most noticeable "wrong" element in early comparisons; tracing on a
4× crop fixed it. Size differs per scene (50–222 px) because the reference scales it with the camera.

### D12 · Simplified look-alike brand icons
*Alternatives:* official SVG logos.
*Reasons:* no network/brand assets assumed; they appear for 4–15 frames at ~80 px; look-alikes sized to
the measured boxes are visually sufficient. Emoji (Noto Color Emoji) for 🍌 and 🔥.

### D13 · 1080p via `deviceScaleFactor: 1.5`
*Alternatives:* render 720p and upscale.
*Reasons:* text and vectors re-render sharply at 1.5×; plates (720p sources) are upscaled by the browser
anyway, so nothing is lost. All coordinates stay in 1280×720 space.

### D14 · Pipe PNG screenshots into ffmpeg
*Alternatives:* write 870 PNGs to disk then encode.
*Reasons:* no disk churn; lossless intermediate; one command. QA mode writes JPGs instead.

### D15 · x264 `-preset slow -crf 14`, BT.709 tags, faststart
*Reasons:* near-transparent quality for graphics with gradients (avoid banding), correct colour
interpretation in players, streamable file.

### D16 · Plates as per-frame JPEGs (q 86–90)
*Reasons:* ~70–150 KB each, 31 MB total; artefacts invisible under motion. PNG would be ~10× larger.

### D17 · Push-pull inpainting in numpy
*Alternatives:* OpenCV `inpaint` (Telea/NS), AI inpainting models.
*Reasons:* no extra dependencies, fast, excellent on smooth/defocused backgrounds which is what was
under almost every graphic; the redrawn graphic covers the filled area anyway.

### D18 · Typing: measured scroll + glyphs remapped to measured boxes
*Alternatives:* natural text flow with a computed scroll.
*Reasons:* natural flow drifted 20–45 px; the scroll in the reference is irregular (fast between
letters, slow while typing). Both measured.

### D19 · Arch letters: two measured poses + cubic progress + measured exit
*Alternatives:* per-frame component tracking for 22 glyphs.
*Reasons:* the arch only tightens smoothly 453→491, so two poses with an ease-out reproduce it; the exit
whip is one measured x-offset track for the whole group. Much less data, same picture.

### D20 · Feature titles: draw over the plate, except where the plate already holds them correctly
*Reasons:* "Image" is interleaved in depth with flying photos and "Motion" is smeared by the whip on
617–621 — redrawing those can't beat the footage. Elsewhere titles are drawn from measured tracks.

### D21 · Logo squiggle as a Catmull-Rom spline through traced points
*Reasons:* 23 points read off a 3× crop give a smooth path that is easy to adjust point by point; it is
used for the draw-on (dashoffset) and the inverted lockup.

### D22 · Mean absolute difference on 320×180 as the score
*Alternatives:* SSIM, PSNR, perceptual metrics.
*Reasons:* simple, explainable, monotonic with visible error at this scale, robust to sub-pixel offsets.
Used for prioritising, not as the only judge.

### D23 · What not to chase
Particle positions, exact SF glyph shapes, frames 227–232 (no clean footage), the exact colour noise of
lifted plates. Classified APPROXIMATE up front so time went into what is visible.

### D24 · Brief in the user's language, training docs in English
*Reasons:* `BRIEF.md` is a deliverable for the user (Russian); `docs/` is training material for models
and engineers (English: widest model comprehension, matches code identifiers).

### D25 · Commit generated assets (plates, final renders)
*Alternatives:* Git LFS, regenerating on demand.
*Reasons:* total size ~55 MB, well within GitHub limits; the repo works immediately after clone;
regeneration scripts are included for when the reference or masks change.
